# 微信记工助手

Windows 桌面软件原型。用 PySide6 接收微信群聊天截图，通过本机 Tesseract OCR 识别文字，以规则提取记工信息。按件计算数量 × 单价；计时统一按 **15 元/小时**计算。不使用 AI 或付费 API。

## Windows 下载、安装、启动

1. 在 GitHub 仓库页面选择 **Code → Download ZIP**，解压到一个普通文件夹。也可以用 Git 克隆仓库的开发分支。
2. 安装 [Python 3.10 或更新版本](https://www.python.org/downloads/windows/)，安装时勾选 `py launcher`。
3. 安装 Windows 版 Tesseract OCR，勾选或额外安装 `chi_sim` 简体中文语言数据，并将 Tesseract 安装目录加入系统 PATH。安装后重新打开程序。
4. 双击项目文件夹内的 `start_windows.bat`。首次启动会自动创建 `.venv` 并安装 Python 依赖；需要联网。后续双击同一个文件启动。

若 Windows 提示找不到 Tesseract，检查 PATH 是否包含 `tesseract.exe` 所在目录，以及其 `tessdata` 目录下是否有 `chi_sim.traineddata`。一键脚本不负责安装 Python 或 Tesseract。

## 使用流程

1. 程序已内置17名正式员工；点击「设置员工和群」，每行填写一个群名（最多3个）。群配置保存在当前 Windows 用户的 `%APPDATA%\WechatWorkRecorder\settings.json`；昵称绑定保存在同目录的 `bindings.sqlite3`。正式员工姓名与稳定工号来自程序内置的 `employees.json`。
2. 可从微信批量复制聊天文字，点击「导入微信复制文字」；也可复制截图，选中对应群后按 `Ctrl+V`。程序自动调用本地 OCR，并解析能明确识别的行。如果 OCR 文本中只出现一个已配置的群名，会自动选择该群；否则必须人工选择。
3. 初次发现未绑定的微信昵称时，程序要求从正式员工名册中手动选择；确认后按微信群写入本机 SQLite，重启仍可使用。「管理昵称绑定」可查看、添加、修改或解除关系。未确认或冲突的昵称会阻止保存。核对 OCR 原文和表格。日期、员工昵称、货号、数量、单价和工时可分布在多行；程序沿用最近明确的日期与员工。可修改原文后点「解析文字」，也可直接编辑表格、用「手工添加记录」补充记录。修改原文后必须重新解析。未解析或疑似重复的记录会阻止保存，需人工核对。
4. 点击「确认并保存模拟账本」，再次确认后选一个**新的** `.xlsx` 文件名。程序拒绝覆盖现有文件。该文件仅用于测试，不会写入真实工资表。

### Windows + WPS 分列复制测试（先用账本副本）

1. 在 Windows 中复制一份账本，**只打开副本**的对应月份表。选定连续的目标行，核对 B:D、F、H:I 为准备填入的区域，且这些区域没有合并单元格；记住首行行号。
2. 检查这些行的 J 列已有工资公式、K 列合并和小计符合原表。若 J 列没有公式，先在副本中补齐并核对；软件不会向 J 列写入金额或公式。
3. 在软件中核对全部记录，点击「复制 WPS 第1步：B:D」，确认后在副本目标首行的 **B 列**粘贴日期、工号、姓名。
4. 回软件点击「第2步：复制 F」，在**同一首行**的 F 列粘贴货号/计时；再点「第3步：复制 H:I」，在同一首行的 H 列粘贴数量/工时、单价。每一步都先复制、再到 WPS 粘贴；不要跳步或换起始行。
5. 对照软件明细逐行检查列值和 J 列公式计算的工资；确认 E、G 未被清空，K 列布局与小计未变化。测试满意后再决定是否在正式账本中手动操作。

软件仅写入系统剪贴板，不直接打开或修改账本。三段复制避免在粘贴数据中包含 E、G、J、K；但软件无法读取 WPS 当前选区，也无法确认粘贴是否成功或避免用户重复手动粘贴。

解析示例：`2026-10-18 张三 货号 AB-123/45 数量 10 单价 2.5`、`2026/10/9 雪琴 8513-7 70*1.7` 或 `2026-10-18 张三 计时 3 小时`。紧凑计件写法支持 `*`、`×`、`x` 等乘号；货号中的横杠属于完整货号。支持 `3小时30分`、`3.5小时`、`计时3.5`、`计时3小时半`；不能确认的工时会提示人工核对。同一截图内的完全相同记录会被标记为疑似重复，同一次程序运行中再次保存相同记录会被阻止；跨程序重启的重复导入尚无持久校验。真实微信截图布局多变，仍可能需要人工整理。窗口显示已识别记录的工资总计。看起来像记工内容却无法解析的行会提示人工核对；OCR、群名检测和规则解析均需逐条核对，不能直接用于正式发薪。

## 开发和测试

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -e '.[test]'
.venv\Scripts\python.exe -m pytest
```

项目模块：`ocr.py` 负责本地识别，`parser.py` 负责规则解析，`employees.py` 和 `settings.py` 管理员工及群名，`payroll.py` 计算金额，`workbook.py` 定义真实账本接口并生成模拟表，`app.py` 实现窗口。

真实 WPS Excel 工资账本的工作表、列映射和重复记录处理尚未确定，`UnconfiguredWorkbookWriter.write_copy` 会拒绝写入。需要账本脱敏模板或字段说明后才能开发这一部分。尚未制作或验证 Windows 安装包；未来可用 PyInstaller 打包，但仍需处理 Tesseract 和中文语言数据的安装或分发。

## 正式员工名册

微信昵称绑定必须使用经过核对的17名员工工号和姓名。将17条记录放在 `src/wechat_work_recorder/employees.json`，格式为 JSON 数组，每项含 `employee_id` 和 `name`；同一名册会随程序打包。首次启用前核对名单，后续若名册与本地绑定数据库不一致，程序会拒绝继续，避免绑定错位。仓库已按提供的17名员工正式名单内置名册；请在首次正式使用前核对姓名和工号。名册采用以下格式：

```json
[
  {"employee_id": "AM-1001", "name": "美娟"},
  {"employee_id": "AM-1002", "name": "李莹"}
]
```

完整17名员工见 `src/wechat_work_recorder/employees.json`。程序只接受精确且已确认的同群昵称绑定；不会根据昵称相似程度猜测员工。真实工资账本仍不会被修改。
