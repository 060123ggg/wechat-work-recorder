# 微信记工助手

Windows 桌面软件原型。用 PySide6 接收微信群聊天截图，通过本机 Tesseract OCR 识别文字，以规则提取记工信息。按件计算数量 × 单价；计时统一按 **15 元/小时**计算。不使用 AI 或付费 API。

## Windows 双击启动（本次主交付）

本轮分支为 `fix/message-review-navigation`，基于最新完整版本 `feat/message-price-upgrade`，不是旧版 main。打开 [Actions 构建列表](https://github.com/060123ggg/wechat-work-recorder/actions/workflows/windows-installer.yml?query=branch%3Afix%2Fmessage-review-navigation)，选择本分支最新**成功**运行，在 **Artifacts** 下载 **WeChatWorkRecorder-Windows-Portable**。

**完整解压 ZIP 到新文件夹，双击「启动微信记工助手.bat」**：先出现黑色窗口，稍后打开助手。确认标题版本 **0.2.1**。支持64位 Windows 10/11，包内带 Python、PySide6、Tesseract 与简体中文 OCR，不需要另装 Python，不需要安装程序。不要只移动一个 exe，旁边的 `_internal`、`tesseract` 等文件夹必须保留。不要在 ZIP 预览内直接打开。附件需要登录 GitHub，默认保留30天。程序未签名，运行前核对仓库及构建来源。

关闭旧程序后再启动新版。本机资料继续保存在当前用户的 `%APPDATA%\WechatWorkRecorder`，程序目录与资料目录分开；解压到新文件夹不会覆盖旧测试版本。本版不改变本机数据结构，不覆盖名册、昵称、价格或以前的工资历史；忽略/合并只在既有审核表追加一条说明。备份该资料目录后测试更稳妥。家里、厂里电脑各有独立资料，不自动同步。

可选安装包仍在同次运行的 **WeChatWorkRecorder-Windows-Setup** 中，解压安装 `WeChatWorkRecorder-Setup-0.2.1.exe` 后从桌面图标启动。它与便携版读取相同的用户资料，不能同时打开两个版本。此次优先使用上面的便携版。

源码双击方式仍保留：下载本轮分支 ZIP，先安装 [Python 3.10+](https://www.python.org/downloads/windows/) 以及带 `chi_sim` 的 Windows Tesseract，再双击根目录 `start_windows.bat`。源码脚本会联网安装依赖；便携版没有这些前置要求。

## 0.2.1 消息查看与审核

保留原有员工/昵称、项目价格库、批量文字、截图OCR、分组工资和WPS三段复制。完整原文中的每条消息之间增加留白和绿色分隔线；显示修饰不写入文字，不改变解析行号。问题区合并成一个列表，按消息序号、原文行号排列，显示昵称、绑定姓名、日期和原因，长内容自动换行。

点击问题会自动滚动到原文问题行、同步选中消息标题，并用浅黄色标出完整消息、橙色标出问题行，然后打开统一审核窗口。窗口可查看完整消息及本次工作原文，取消即暂不处理。消息标题可单独点击，跳到该消息开头。

重复计时审核修复了“没有货号却查询货号历史价格”的异常。疑似重复项必须主动选择「独立工作，另计工资」「确实重复，忽略」「合并到已有记录」之一；合并保留已有工资，不叠加工时或金额、不删除历史记录。取消或未选择均保留待核对，继续阻止复制。重复计件也使用同样的决策。裸写 `3.5×15` 不自动入账；与已有计时匹配时仅生成待审核的计时草稿，仍须确认类型和是否独立工作。

忽略/合并只适用于当前未改变的消息批次。修改原文、切换群或重启重新导入后会再次检查，不使用旧的忽略决定静默漏记。多项工作挤在同一原文行且无法安全分开时，请先拆行再解析。详见 [Windows 最简验收步骤](docs/message-review-testing.md)。

## 0.2 升级与识别说明

关闭旧程序，先备份 `%APPDATA%\WechatWorkRecorder`，再运行 0.2 安装程序覆盖安装到同一位置。员工名册、群设置、昵称数据库继续使用原目录；旧版价格文件首次保存为新格式前会备份为 `catalog_overrides.v1.backup.json`。新库保存在 `catalog_overrides.json`；本机已复制/已保存项目与原文追溯保存在 `imports.sqlite3`。这些文件只保留在本机，卸载程序不主动删除；不要将其提交到 GitHub。降级后不要使用旧版程序修改新价格库。

新增支持 `8510 154个*0.55`、`8510-1 216个*0.55`、`8510-216个×0.55`（最后一项为 8510、216 个），完整后缀货号不因价格被改写。中文项目、个/件/捆等单位及不同乘号可混用。`猫食盆2件*10` 后的 `1件*5` 只在同一条消息内继承猫食盆；遇到新项目、计时或不明确工作后不跨越继承。`计时拆箱7*15`、`计时。3x15` 均按 15 元计算并保留备注。

遇到新项目会弹出新增窗口并预填消息价格；取消后保留原文和待核对项。未知发送人、无效日期、缺失/特殊单价、含糊数量与疑似重复各有具体原因；可在完整人工审核窗口中确认。消息列表和待核对区保留编号及原文行号，所有工作项完成核对后才能整批复制到 WPS。最终复制确认窗口可一次确认列出的单价差异。

## 使用流程

1. 首次启动点击「管理正式员工名册」，软件会预填「设置员工和群」里已有的员工姓名，并提供待核对的工号建议；确认17名员工后保存在本机。随后点击「设置员工和群」，填写群名（最多3个）。群配置保存在当前 Windows 用户的 `%APPDATA%\WechatWorkRecorder\settings.json`；昵称绑定保存在同目录的 `bindings.sqlite3`。正式员工姓名与稳定工号来自本机私有名册。
2. 可从微信批量复制聊天文字，点击「导入微信复制文字」；也可复制截图，选中对应群后按 `Ctrl+V`。程序自动调用本地 OCR，并解析能明确识别的行。如果 OCR 文本中只出现一个已配置的群名，会自动选择该群；否则必须人工选择。
3. 初次发现未绑定的微信昵称时，程序要求从正式员工名册中手动选择；确认后按微信群写入本机 SQLite，重启仍可使用。「管理昵称绑定」可查看、添加、修改或解除关系。未确认或冲突的昵称会阻止保存。核对 OCR 原文和表格。日期、员工昵称、货号、数量、单价和工时可分布在多行；程序按消息头确定发送人，正文工作日期优先于微信发送日期；月日格式用发送年份补全，未知发送人必须人工选择。可修改原文后点「解析文字」，也可直接编辑表格、用「手工添加记录」补充记录。修改原文后必须重新解析。未解析或疑似重复的记录会阻止保存，需人工核对。
4. 下方工资主表按日期和正式员工编号分组，分别显示每项金额，并将同一员工当天的合计工资跨行合并。消息列表显示第 N 条、绑定姓名和核对状态；这些标注不改变微信原文。点击「确认并保存模拟账本」，再次确认后选一个**新的** `.xlsx` 文件名。模拟表主工作表使用同样的八列分组格式，另设「审核追溯」工作表保存备注与原文。程序拒绝覆盖现有文件，不会写入真实工资表。

解析示例：`2026-10-18 张三 货号 AB-123/45 数量 10 单价 2.5`、`2026/10/9 测试员工 8513-7 70*1.7` 或 `2026-10-18 张三 计时 3 小时`。紧凑计件写法支持 `*`、`×`、`✘`、`x` 等乘号；货号中的单横杠属于完整货号。历史库中已有完整货号时，`--` 和 `~~` 可作为货号与数量之间的分隔符，例如 `8393--6*4` 记 24 元，`8352~~270*0.6` 记 162 元。未知货号或边界不明的写法须人工确认。支持 `3小时30分`、`3.5小时`、`计时3.5`、`计时3小时半`，以及 `计时3（贴标套袋打包）`、`计3.5快递`、`计2.5*15快递` 等带工作备注的写法。备注留在记录中，并写入模拟账本的「审核追溯」工作表；下方工资主表不显示备注；`*15` 仅核对已确认时薪，工资仍按每小时15元计算。不能确认的工时会提示人工核对。同一截图内的完全相同记录会被标记为疑似重复，本次导入中及本机以前已复制/已保存的相同或高度相似项目会提示疑似重复；用户确认确实是独立工作后才会加入第二条。真实微信截图布局多变，仍可能需要人工整理。窗口显示已识别记录的工资总计。看起来像记工内容却无法解析的行会提示人工核对；OCR、群名检测和规则解析均需逐条核对，不能直接用于正式发薪。

## 开发和测试

### 在 Windows + WPS 中测试分列复制

先复制一份账本，只在**副本**的对应月份表测试。选定连续的目标行，检查 B:D、F、H:I 没有合并单元格，J 列已有工资公式，K 列原有布局和小计正常；若 J 公式缺失，先在副本补齐并核对，软件不会写入 J。**先将目标 F 列设为文本格式**，避免 `8513-7` 被 WPS 当成日期。

核对软件中的员工、日期、项目、数量、单价和工资后，依次点击「第1步：复制 B:D」并从副本目标首行的 B 列粘贴、「第2步：复制 F」并从**同一首行**的 F 列粘贴、「第3步：复制 H:I」并从同一首行的 H 列粘贴。最后逐行检查 J 列公式金额、E/G 原内容和 K 列合并布局。三段数据不包含 E、G、J、K；软件只写系统剪贴板，无法读取 WPS 当前选区或验证用户是否真的完成粘贴。测试时要重新复制同一批记录，软件会要求再次确认，以免误粘贴重复记录。

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -e '.[test]'
.venv\Scripts\python.exe -m pytest
```

项目模块：`ocr.py` 负责本地识别，`parser.py` 负责规则解析，`employees.py` 和 `settings.py` 管理员工及群名，`payroll.py` 计算金额，`workbook.py` 定义真实账本接口并生成模拟表，`app.py` 实现窗口。

真实 WPS Excel 工资账本仍不会被程序直接写入；`UnconfiguredWorkbookWriter.write_copy` 会拒绝写入。三段剪贴板复制须由用户在 WPS 副本中核对与粘贴。Windows 安装包在 GitHub Actions 中构建并执行安装后冒烟测试；真实电脑上的截图 OCR、桌面图标、昵称持久化与 WPS 粘贴仍需实机验证。

## 货号库与本机私有名册

原有 `historical_items.csv` 继续用于完整货号识别，其跨月价格不进入新价格资料库。独立的 `october_prices.csv` 只取自用户提供账本的 **2026 年十月 F/I 列**：39 个项目、54 条价格统计（26 个单价项目、13 个多价项目），不含员工、工号、昵称或工资明细。原账本只读提取，未修改，也不随安装包分发。

升级后，点击「管理货号/项目与默认价」→「完整价格资料库/别名/导入十月价格」→「导入随包十月资料」，确认后才导入本机。单一历史价可作为初始标准价，多价项目保持待确认；已有用户标准价和已确认的 `8513-6 = 1.70` 不被覆盖。选中项目可编辑标准价、单位、多个别名；不同数字货号不得合并或互作别名。也可导入脱敏 CSV，格式见 [价格资料说明](docs/price-library.md)。

没写单价时只使用已确认标准价；多个价格未确认时必须选择或填写。写了不同单价时按本次价计算，并逐次提示标准价、本次价、数量和金额；人工确认只影响这次记录，不修改标准价。修改标准价不改变当前已确认批次、已导出模拟账本或 WPS 中已有工资；新导入使用新标准价。

由于正式员工名单含个人信息，仓库不发布真实名册。首次使用时在软件中点击「管理正式员工名册」；已有姓名会预填，工号需要逐个核对。无需手工创建 JSON。软件会把名册保存在本机 `%APPDATA%\WechatWorkRecorder\employees.private.json`，昵称关系保存在同目录的 `bindings.sqlite3`；重新启动后继续使用。已有昵称绑定时可以更正姓名，但不能直接更换其工号，避免旧绑定指向其他员工。本机文件不要放入 GitHub 仓库。

已知完整货号后的 `--` 或 `~~` 是货号与数量的分隔符；`8393--6*4` 与 `8352~~270*0.6` 在昵称已绑定、日期有效时会直接识别。昵称未绑定时只提示员工身份问题，不会误报数量边界。真正含糊的写法仍显示原文和候选。点击待核对列表可定位并高亮原微信消息；选中该项后点击「核对疑似记工行」，在同一个审核窗口查看原文、消息序号、员工和日期，选择计件或计时，直接修改货号/项目、数量、单价或工时与备注；本项金额会随输入更新。历史货号只提供候选，审核窗口不显示历史次数或参考价统计；标准价未确认且原文没写单价时，会提供十月单价候选供用户主动选择。点击「确认并加入工资表」后，记录立即加入明细并更新当日合计、总工资和待核对数量；点击「取消」不改变记录。原始微信文字不被改写。未解析行不能保存。`8513一6 50*1.7` 等数字间横杠变体会规范为完整货号 `8513-6`。

「打包」等中文工作项目可在「管理货号/项目与默认价」中添加到本机目录；添加后点击「解析文字」，`打包-45*0.2` 会按计件 9.00 元识别。未添加的工作项目仍需人工核对。计时仍按独立的每小时 15 元规则处理，不作为货号/项目添加。

Windows 实机仍需验证微信截图的中文 OCR、焦点在不同控件时的 Ctrl+V、微信复制文本布局、昵称绑定持久化和模拟账本保存。真实工资账本写入仍未开放。
