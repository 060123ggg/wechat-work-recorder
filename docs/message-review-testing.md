# 0.2.1 Windows 最简验收

先退出旧程序、备份 `%APPDATA%\WechatWorkRecorder`。从 README 指向的本轮成功构建下载 Portable 附件，完整解压到新目录，双击「启动微信记工助手.bat」，确认标题0.2.1。无需Python。首次使用按界面指引设置名册/群及绑定；不要把本机资料上传仓库。

## 消息、定位与重复审核

选择一个已设置的测试群，粘贴下文，将“测试昵称”绑定到本机选择的员工（不凭相似名自动认定），点导入或解析：

```text
测试昵称
2026年10月18日 19:40
10.17
8352~~270*0.6
计时3
计时 3×15

测试昵称
2026年10月19日 20:00
计时3.5
3.5×15
```

1. 原文两条消息之间应有明显留白和绿色线；第一条工作日期为2026/10/17，不是发送日期18日。第二条为19日。最初工资：162 + 45 + 52.50 = **259.50元**（3项记录），两个重复候选待核对。
2. 点击第二条问题，应跳到上方 `3.5×15`，完整消息浅黄、问题行橙色，消息标题选中第2条，并弹出一个审核窗口。也可先用方向键选中问题，再点「核对疑似记工行」。应预填计时3.5、固定时薪15、本项52.50元。点取消：总额、待核对均不变。
3. 重开第二项，选“独立工作，另计一项工资”并确认：总额 **312.00元**，4项记录、剩1项待核对。再次解析不能多出一条记录。
4. 第一条重复项选“确实重复，忽略”或“合并到已有记录”并确认：总额仍 **312.00元**、4项记录、待核对0；已有计时不能被删除或再加算。合并不是叠加工时。
5. 在原文末尾追加 `计时2` 后重新解析：旧忽略/审核不应无条件沿用，重复项应重新待核对。点击“第1条”标题应定位消息开头。用更多消息测试上下滚动和长问题换行。
6. 另测 `8513-65*1.7`：审核计件8513、数量65、单价1.7，应新增110.50元，同时更新当日合计、总额与待核对数。单价差异、无效日期和未绑定员工仍要拦截。打包/别名和已确认标准价应继续可用。

## 原功能与资料

- 关闭重开软件，核对已有名册、昵称、项目别名、标准价仍在；复制/保存过的项目重新导入仍有重复提醒。新电脑不会自动拥有另一台电脑的私有资料。
- 焦点分别放在文字区、按钮、群选择框和工资表，Ctrl+V粘贴微信截图；核对中文OCR及混合计件/计时。若OCR失败，不得留下旧记录供保存。
- 只新建模拟账本或使用工资表**副本**。WPS先将F列设为文本；同一首行依次粘贴B:D、F、H:I，确认E/G未覆盖、J公式与K合并合计正常。软件无法核实选区/是否实际粘贴。

上述是需要用户完成的实机步骤，不代表开发环境已验证真实微信或WPS操作。自动化只覆盖合成数据、Qt离屏鼠标操作与构建启动。
