# 0.2 本机项目价格资料

本版从完整安装版 `1683fc8` 升级；工资计算继续使用 Decimal，计时固定 15 元/小时。没有 AI 或真实账本写入。

## 来源与导入

随包 `october_prices.csv` 是原账本 **10月** 工作表的 F/I 列脱敏汇总；G 列只有有效单位才保留，否则标为件。39 个项目、54 条价格统计：26 个单价项目、13 个多价项目。只统计可识别项目且 I 列有有效非负数字的行；不从其他月份补价，不导出员工列，不上传原账本。未提取的特殊写法和缺失价格仍需在本机手工补充。

首次打开价格管理的完整资料库，状态栏会显示十月价格是否导入。用户选择「导入随包十月资料」并确认后，单价项目初始化标准价，多价项目保持空白。已有用户标准价保持不变。原有跨月货号 CSV 只用于识别身份，不参与标准价格初始化。

外部 CSV 使用 UTF-8（可带 BOM），列为：

```csv
code,price,count,unit,month,source
8377,0.30,4,个,2026-10,十月脱敏价格
8510,0.55,12,个,2026-10,十月脱敏价格
8510,0.60,14,个,2026-10,十月脱敏价格
```

本版仅接受 `month=2026-10`；不要放员工、工号、昵称或工资。所有行先校验再导入。历史价格条目与当前标准价分别保存；历史次数不会参与选价。选择本次价格不等于修改标准价，标准价须在资料库里明确保存。别名必须指向唯一完整项目，不同数字货号不能互相作别名。

## 本机保留与追溯

数据目录为 `%APPDATA%\WechatWorkRecorder`，安装和卸载均不主动删除。价格文件 `catalog_overrides.json` 原有 `codes/defaults` 会保留，首次写新格式前生成一次 `catalog_overrides.v1.backup.json`。员工名册、群和昵称数据库沿用原路径。

完成三段复制或保存模拟账本时，`imports.sqlite3` 保留本机重复提醒和原文、行号、消息号、标准价快照、单价来源等输出追溯。它只证明曾完成复制/模拟保存，不证明 WPS 已粘贴或实际发薪。模拟账本的「审核追溯」页也保留这些信息。新安装电脑无此历史时，无法核对在别的电脑或软件中发生的重复。

## Windows 安装与人工回归

1. 下载对应分支成功 Actions 的附件，运行 `WeChatWorkRecorder-Setup-0.2.0.exe`；标题应为「微信记工助手 0.2.0」。验证桌面启动、原有员工名册与昵称仍在，退出后重启再检查。
2. 在价格管理导入随包十月资料，核对 8510、8510-1 多价待确认，8377 初始 0.30，8510-2 初始 0.60，8513-6 仍为已确认价 1.70。按实际业务确认当前标准价；示例价格不代表批准变价。
3. 用合成昵称绑定到本机测试员工，粘贴发送时间 `2026年10月18日 19:40`、正文 `10月17号` 与计时/计件多项。日期应为 10/17；`8510-216个×0.55` 应保留 8510、216 个。8377 填写 0.20 而标准 0.30 时应提示差异。
4. 测试 `猫食盆2件*10`、`1件*5`、`打包20捆*0.2`、`计时5*15`。新项目必须先确认；单次 5 元审核后标准价不变。取消审核不得丢掉原文。未知发送人必须由人选择，日期不能变成昵称。
5. 用真实微信截图分别将焦点放在原文、按钮、群下拉和工资表格，按 Ctrl+V 检查中文 OCR；OCR 结果必须逐项核对。用真实微信多选复制检查消息边界，不能保证所有微信布局和图片质量都能自动识别。
6. 只用新建测试表或账本副本测试 WPS；F 目标区预设文本，从同一首行依次粘贴 B:D、F、H:I。目标区含隐藏行列、合并单元格或缺 J 公式时先人工检查。核对 E/G 未覆盖，J 公式与 K 合计正常。软件无法读取 WPS 当前选区或确认粘贴完成。
7. 未核对完同条消息时复制应被拦截；复制过的相同/近似项目重启后应提示疑似重复。确为独立工作时人工明确确认；测试重复制同一批应使用「确认重新复制」，不要据此认定已经入账。

同一行塞入多条不明确的计件项目、完全连写且没有边界的货号数量、无法确定年份或发送人、未支持的口语时间仍需人工处理。无结构的聊天、复杂截图与 OCR 错字不保证百分之百识别。原始内容和待核对原因始终保留。
